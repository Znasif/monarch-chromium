# Architecture & Engineering Decisions (`DECISIONS.md`)

This log records open questions encountered during autonomous agent runs, the conservative default chosen for each, and the rationale (per `docs/LONG_TERM_PLAN.md` §5).

| ID | Step | Question | Chosen Default | Reason |
|---|---|---|---|---|
| **D-01** | Step 0 | Does KeySoft read GeckoView 158's duplicate container + text accessibility nodes twice or skip them during `H`/`L`/`B` quick-nav? | Keep Steps 1–4 100% engine-neutral (`tactile-core`, `bridge`, `tier2`). Default `app/` `BrowserEngine` to `SystemWebViewEngine` with a runtime toggle to `GeckoEngine`. | `uiautomator dump` on the Monarch showed WebView 109 exposes clean 1:1 accessibility nodes, while GeckoView 158 duplicates headings, links, and labeled inputs. Engine neutrality preserves both options until human hardware verification completes. |
| **D-02** | Step 0 | Should `Component.bbox` store normalized `[ymin, xmin, ymax, xmax]` coordinates or integer pin coordinates (`0..95` × `0..34`)? | Store both `bbox: NormalizedBox(ymin, xmin, ymax, xmax)` in `0.0f..1.0f` (with `fromGemini1000` helper) and `pinBox: PinRect(minX, minY, maxX, maxY)` in `0..95` × `0..34`. | Normalized coordinates are required for `gemini-4-argon` alignment and lossless `1x..8x` viewport zoom/pan re-projection, while integer `PinRect` bounds allow fast integer `HitGrid` and `ComponentGraph` operations. |
| **D-03** | Step 0 | When two components or their 1-pin halos overlap on the 96×35 canvas, which component ID wins in `HitGrid.lookup(x, y)`? | Direct component pins always beat 1-pin halo pins; among competing direct pins (or competing halo pins), smaller `pinBox.area` wins, breaking ties by later insertion index. | Child sub-components (e.g., an organ inside a body diagram or a character inside a comic panel) have smaller bounding boxes than their parent containers and must remain reachable by touch. |
| **D-04** | Step 0 | What should `HitGrid` (size `96 * 40 = 3840`) return on separator row `35` and Braille caption rows `36..39`? | Clamp all component and halo stamping to rows `0..34`. Return `0` (`NO_COMPONENT`) on row `35` and `-1` (`CAPTION_REGION`) on rows `36..39`. | Prevents 1-pin halos at the bottom of the tactile canvas (row `34`) from bleeding into the separator row or triggering false component haptic pulses when the user reads the Braille caption bar. |
| **D-05** | Step 0 | How should the compiler enforce the `<= 25%` raised-pin fill ceiling (`<= 840` of `3,360` canvas pins) when a complex SVG or bitmap contour is too dense? | Never dither or drop isolated pixels from 1-pin lines. For SVGs, prune smallest interior sub-paths by bounding perimeter; for raster images, raise the adaptive edge threshold and prune shortest connected contour chains (`< 4` pins) until fill `<= 25%` (`<= 20%` overview target). | Preserves continuous 1-pin tactile contours that blind users can trace with a finger, whereas dithering or random thinning turns lines into unreadable tactile sandpaper. |
| **D-06** | Step 0 | In `bridge/`, should image-to-button promotion replace `<img>`/`<svg>`/`<canvas>` elements in-place or insert an adjacent `<button>`? | Keep the original element in the DOM with `aria-hidden="true"`, and insert `<button type="button" class="monarch-tactile-btn" data-monarch-target-id="...">Explore tactile image: <label></button>` immediately before it. | In-place DOM replacement breaks page scripts that hold references to `<canvas>` or `<svg>` nodes and disrupts CSS grid/flex sizing needed for geometry capture. |
| **D-07** | Step 0 | What thresholds classify an image as decorative or tiny in `bridge/` so it is skipped during button promotion? | Skip elements with `role="presentation"`, `role="none"`, `aria-hidden="true"`, explicit empty `alt=""` (without `aria-label`/`<title>`/`<figcaption>`), hidden visibility/display, or rendered size `< 32×32` CSS px (except inline `<svg>` with `<title>` or `aria-label`). | Avoids cluttering KeySoft's `B` (Button) quick-nav list with tracking pixels, spacer icons, and decorative borders while capturing all meaningful diagrams and figures. |
| **D-08** | Step 0 | How should `Tier2SceneMerger.hotSwap` reconcile focus when Tier-2 `gemini-4-argon` results arrive while the user is exploring a Tier-1 scene? | Preserve active `Viewport(zoom, panX, panY)`, map the focused Tier-1 component to the Tier-2 component with highest bounding-box IoU (`>= 0.25`) or nearest centroid, and hot-swap `ComponentGraph` and `HitGrid` in-place. | Prevents jarring viewport resets or lost cursor context while upgrading labels, descriptions, and hierarchical decomposition live. |
| **D-09** | Step 0 | How should Gradle be structured at the repo root when the Linux sandbox lacks the Android SDK required by `engine-test/`? | Create a root Gradle 9.6.0 project in Step 1 that includes pure-JVM modules (`:tactile-core` in Step 1, `:tier2` in Step 4) while leaving `engine-test/` as a standalone Android project for device builds. | Allows `./gradlew :tactile-core:test` and `./gradlew :tier2:test` to run cleanly in the Linux sandbox with OpenJDK 21 without requiring the Android SDK. |
| **D-10** | Step 1 | How should `NormalizedBox.toPinRect` round normalized box boundaries onto the `96×35` pin grid so narrow inter-panel gutters (like `9 px` out of `666 px` in `xkcd-327`) are not collapsed? | Use inward box rounding (`ceil` on `minX`/`minY`, `floor` on `maxX`/`maxY`) whenever a box spans `>= 1.0` pin. | Nearest-integer rounding (`roundToInt`) collapses `[43.0, 44.28]` into adjacent columns `43` and `44` (`0` blank columns), merging adjacent panel borders. Inward rounding guarantees `>= 1` blank pin column for any source gap `> 1` pin wide while staying within the `6 px` source tolerance. |
| **D-11** | Step 1 | How should `HitGrid.stampScene` treat components whose `raisedPins` array is empty at `1x` overview (such as speech bubble text zones where `"textAsPins": "none"`)? | When any component in the scene has explicit `raisedPins`, only stamp `raisedPins` and their 1-pin halos into `HitGrid`; fall back to stamping `pinBox` interiors only when all components in the scene have empty `raisedPins`. | Prevents invisible speech-bubble bounding boxes (which have no raised pins at `1x`) from masking user-drawn lines or panel/figure pins on `HitGrid`, while still supporting box-only unit-test fixtures. |
| **D-12** | Step 1 | How should `splitComponent`, `mergeComponents`, `reParentComponent`, and `PinDrawingLayer` persist across page reloads and reuse across pages? | Store both the edited `Component` tree (including `baseNormalizedPins`) and `PinDrawingLayer` (`AttachedNormalizedPin` points in `[0, 1]` coordinates) in `SceneEditStore` keyed by `sha256Hex(imageBytes)` using a zero-dependency JSON serializer. | Keying by SHA-256 of raw image bytes ensures identical images on any URL reuse user edits and drawings without network calls or third-party serialization plugins. |
